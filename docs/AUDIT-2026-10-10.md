# Backend audit — 10 October 2026

## Result and scope

Follow-up: the [running-backend Playwright MCP audit](BROWSER-AUDIT.md) subsequently verified real MongoDB, Redis, SMTP capture, browser cookies/CORS, WebSockets and a BullMQ deletion job. Its live-run evidence supplements the controlled-adapter tests described below; external media/AI/cloud deployment remain unverified.

The local backend checks pass after the fixes below. This is a source review and automated local regression audit, not a penetration-test certificate or a claim that every possible defect has been eliminated. The frontend and production deployment have not been built or verified in this audit.

The baseline had 34 passing tests. Six additional tests first reproduced real failures, then passed after fixes. The expanded suite has 52 tests against HTTP routes, an isolated MongoDB replica set, and Socket.IO. External mail, storage, AI, media, and Redis coordination are controlled adapters. Their real services, distributed lock behavior, scaling, browser permission flows, and network failure modes still need staging verification.

## PDF-derived backend additions

- Account preferences: validated locale/time zone, optional analytics/marketing preferences off by default, timestamps, and cookie mutation CSRF checks. This API does not install tracking, implement an anonymous browser banner, or establish legal compliance.
- Onboarding: read completion status and workspace count; complete only after joining or creating a workspace.
- Support: persisted workspace requests, own-request listing, administrator-only workspace listing and responses, rate limits, and audit metadata. No email or external ticket system is contacted.
- Help: public JSON articles at `/help` describing implemented account, consent, meeting, and support behavior.
- Maintenance: API `503 MAINTENANCE` with `Retry-After`, readiness 503, liveness available, and Socket.IO connection/event rejection. Provider callbacks remain available. Existing SFU sessions and workers must be drained separately for a full outage.
- Search isolation: `X-Robots-Tag: noindex, nofollow, noarchive` on backend responses. `/robots.txt` allows crawling so the header can be observed. Authentication remains the actual private-data boundary. No private meeting sitemap is generated.
- Disclosure: `/.well-known/security.txt` appears only when a real contact and unexpired date are configured. No fictional security mailbox or response SLA is published.

## Verification record

Run from the repository root:

```sh
npm run security:check
npm run validate:deploy
npm run format:check
npm run docs:export
```

The final local run passed 52 tests, TypeScript checking, compilation, the secret scan, formatting, and YAML parsing; npm reported zero known dependency vulnerabilities. The dependency result is a point-in-time package advisory check, not proof that dependencies are vulnerability-free. YAML parsing does not validate Kubernetes admission, cloud permissions, or running containers.

Test coverage includes verification/reset/login, MFA and refresh replay, cookie CSRF, origin checks, Mongo operator injection, JWT tampering, oversized bodies, tenant isolation, private meetings, lobby/removal, consent, audio sealing, AI evidence, explicit task acceptance, signed callback replay, cleanup, Socket.IO authorization, lifecycle preferences and support permissions.

## Remaining release verification

1. Install/run Docker or use a staging environment, build/scan the image, and start the full API/worker/Redis/Mongo/S3/media stack. Docker was unavailable here.
2. Supply staging provider accounts and validate real Google OAuth, SMTP delivery, S3 permissions and lifecycle, OpenAI transcription/summary, LiveKit recording, webhook retries, TURN and two-browser media flows.
3. Test distributed locking, concurrent replicas, queue recovery, provider latency, reconnects, long recordings, admission/removal under load, and graceful shutdown. Redis lock renewal is coordination, not a formal fencing guarantee across every provider side effect.
4. Verify TLS, gateway forwarding, WAF limits, private networking, least privilege, secret management, encrypted backup restoration, observability and incident ownership. Run authenticated DAST and an independent penetration test on the authorized staging environment.
5. Build the frontend states and public policy pages identified in [the complete PDF mapping](LAUNCH-CHECKLIST.md). Resolve business details in [policy drafts](POLICY-DRAFTS.md).
6. Configure monitored disclosure and support ownership. Agree retention and deletion procedures for account data, support requests, audit/job metadata and backups; automated meeting retention does not cover every record type.
7. Use the production domain and account access to verify Search Console, public sitemap, metadata, rich-result eligibility, Open Graph, indexing diagnostics and consent-aware analytics. No account configuration or indexing success is claimed from local files.
